# Decisions

Only decisions needed to resolve details left unspecified by the staged refactor plan are recorded here.

| Phase | Decision | Rejected alternative | Reason |
| --- | --- | --- | --- |
| 0 | Use the existing screenshot example's SHA-256 of each emitted PNG as the style/view checksum. | Add a new image-hash implementation to production code. | The example already emits deterministic baseline images, so hashing files is the smallest measurement method. |
| 0 | Measure GPU baseline with a temporary, untracked harness using the existing Realistic game scene, offscreen renderer, and readback. Report the readback-including time separately from window presentation. | Infer GPU performance from the interactive preview or compare different scenes. | The existing benchmark is CPU-only; this gives a repeatable GPU measurement on the available adapter without adding a lasting product feature. |
| 1 | Dependency policy lists direct dependencies including normal, dev, build, and optional entries. | Ignore dev/optional edges. | Those edges still affect workspace tooling and feature-enabled builds, and the plan disallows unapproved crate references. |
| 1 | Keep example directories as documentation placeholders until Phase 13 creates executable packages. | Add nonfunctional example packages to the workspace now. | They have no specified implementation until Phase 13 and placeholder packages would add noise to every intermediate workspace build. |
| 4 | Represent app frame/fixed time with `std::time::Duration`; when the eight-step cap is reached, discard excess whole steps but retain the fractional remainder. | Use floating-point seconds and clear the full accumulator after a capped frame. | Duration avoids avoidable timing drift, and retaining the remainder follows the specified “drop excess” behavior while preserving sub-step progress. |
| 5 | Apply queued OS input before `VirtualInput` events in each `First` stage; a focus-loss event releases all held keys and mouse buttons. | Merge sources nondeterministically or preserve held input after losing window focus. | A fixed source order keeps scripted runs reproducible, and clearing held input matches the existing keyboard-state behavior on focus loss. |
| 6 | Make the new `FramePlan` generic over scene data and keep the old API renderer trait as a compatibility adapter until its legacy scene/material types move in Phase 7. | Add a forbidden dependency from `engine_render` to `voxelworks-scene`, or prematurely move scene-rendering types out of their assigned phase. | The dependency table excludes old scene crates from `engine_render`; generic frame data preserves the boundary and lets the old renderer keep compiling. |
| 7 | Keep `Scene<'a>` as a type alias for the newly named `RenderScene<'a>` until Phase 9 removes legacy scene imports. | Rename the public type without a compatibility alias. | The old API and GPU renderer still name `Scene`; the alias avoids changing their behavior during the staged migration. |
| 7 | Keep the fixture golden integration test in the legacy CPU crate while the CPU implementation moves. | Add the old testkit crate as a dependency of `plugin_rendering` or duplicate its fixture data. | The allowlist excludes testkit from production plugin dependencies, and copying fixture setup would maintain two sources of truth. |
| 10 (pulled forward) | Implement reflection and scene foundations before completing Phase 7's ECS rendering bridge. | Add a second render-only global transform type or defer the render bridge. | The specified bridge consumes `engine_scene::GlobalTransform` and `ScenePlugin`; one shared transform source avoids divergent scene state. |
| 11 | Define `VoxelWorldRes` in `plugin_voxel` and re-export it from rendering, so both rendering and physics consume one world resource. | Make `plugin_physics` depend on `plugin_rendering` or duplicate the resource wrapper. | The dependency policy forbids the plugin edge and duplicate wrappers could point at different collision/render worlds. |
| 9 | Rewrite the neutral fixture against the new crates and keep it as `plugin_rendering`'s `tests/common` module, with the CPU golden and CPU/GPU parity tests beside it. | Keep a standalone `testkit` crate wired in as a dev-dependency, or leave the tests in the legacy shim crates. | A test-tree module cannot become a production dependency, so the allowlist needs no testkit exception, and the legacy crates lose their last dev-dependencies. The hashes and parity thresholds are unchanged, which keeps the move behavior-neutral. |
| 9 | Replace the STUDS executable's legacy runner with `engine_app::App` and ordered platform/scene/rendering/audio/game plugins. The renderer-neutral `WindowFrame` connects the game's selected CPU or offscreen GPU renderer to the winit platform runner without introducing a platform-to-renderer dependency. | Keep `run_with_mode` as an adapter, or make `engine_platform` depend on renderer implementations directly. | The new app removes the immediate-mode `App`/`Ctx` trait path; a platform-neutral frame contract keeps dependency direction clean. Legacy shims remain dev-only until the remaining migration and compatibility cleanup are complete. |
| 9 | Delete only the `voxelworks-core` re-exports with no remaining legacy user (`audio`, `physics`) in step 4, and keep `math`, `voxel`, `input` and `time`. | Port `voxelworks-api`, `platform` and `minimal` to the new crates now so all five shims can go. | Those crates are deleted in step 7; porting them would add churn and risk to code that is about to disappear. |

| 9 | Keep `Game` as a compatibility/domain facade, but install its initial values into independent ECS resources and entities for the live runtime. | Rewrite every golden fixture and public helper at the same time as the runtime migration. | The ECS runtime gets separately scheduled player/enemy/pickup systems while existing deterministic fixtures and legacy domain consumers remain compatible. |
| 9 | Expose STUDS renderer choice through `--renderer cpu|gpu|auto` and reuse the existing GPU voxel renderer behind the shared `Renderer<MaterialTable>` and `WindowFrame` contracts. | Keep the game CPU-only or wire a renderer implementation directly into `engine_platform`. | The plugin retains backend ownership and platform remains renderer-neutral. STUDS' voxel GPU rendering remains offscreen/readback; the separate `plugin_render3d` mesh path presents directly to the native surface until voxel chunks are migrated. |
| 3D scene | Store `Transform3D` and `GlobalTransform3D` in `engine_scene` and reuse `Parent`/`Children`; let `plugin_render3d` depend on scene contracts. | Keep a renderer-owned world-space transform and maintain a second, unsynchronized hierarchy. | Parent-child transforms must be shared by mesh rendering, scene serialization and future ray queries. The existing 2D/voxel transform remains separate because its angle and axis convention differs. |

| 3D rendering | Extract camera, built-in mesh, glTF placement and light data into `ExtractedScene3D` in `PostUpdate`, after scene transform propagation. | Query gameplay entities directly inside `FramePass::render`. | A render-facing snapshot separates ECS ownership from GPU command recording and allows future culling, batching and render-graph passes to consume one explicit boundary. |
