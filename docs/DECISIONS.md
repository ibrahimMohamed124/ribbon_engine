> **Decision log.** Rows referring to compatibility stages record the migration decision at that time. The Phase 9 retirement is complete; use `docs/PHASE9.md` for the current final state.

# Decisions

Only decisions needed to resolve details left unspecified by the staged refactor plan are recorded here.

| Phase | Decision | Rejected alternative | Reason |
| --- | --- | --- | --- |
| 0 | Use the existing screenshot example's SHA-256 of each emitted PNG as the style/view checksum. | Add a new image-hash implementation to production code. | The example already emits deterministic baseline images, so hashing files is the smallest measurement method. |
| 0 | Measure GPU baseline with a temporary, untracked harness using the existing Realistic game scene, offscreen renderer, and readback. Report the readback-including time separately from window presentation. | Infer GPU performance from the interactive preview or compare different scenes. | The existing benchmark is CPU-only; this gives a repeatable GPU measurement on the available adapter without adding a lasting product feature. |
| Horror slice / first-person movement | Use the small `Aabb3` + vertical capsule-vs-AABB axis-separated slide helper in `ribbon_plugin_physics` for the static, axis-aligned room boxes and props; reconsider Rapier if the room needs slopes, steps, dynamic rigid bodies or general query APIs. | Add an unused physics dependency before the slice needs its broader features. | The authored room is static and axis-aligned, with no jumps, gravity, stairs or dynamic bodies. The compact solver meets the current walk/stop/slide requirement. It is deliberately scoped and does not replace a future general camera-ray/line-of-sight query API; revisit the physics backend when later interaction and AI work needs those queries. No Rapier dependency is currently declared or allowlisted. |
| Horror slice Phase 1 / visual room | Keep `room.ron` as a small RON description parsed by the example, resolve its model paths through `AssetServer`, and use embedded glTF binary assets for renderable geometry/materials. | Serialize asset handles into the current prefab `TypeRegistry` or introduce game-specific components into `ribbon_scene`. | The existing prefab mechanism registers common transforms but is not yet able to recreate `Handle<ModelAsset>` values or room-specific path/collider/waypoint data from reflected values. The example therefore owns the authored room schema; actual mesh/material loading and all light/shading behavior remain reusable plugin responsibilities. |
| 1 | Dependency policy lists direct dependencies including normal, dev, build, and optional entries. | Ignore dev/optional edges. | Those edges still affect workspace tooling and feature-enabled builds, and the plan disallows unapproved crate references. |
| 1 | Keep the example directories from the original scaffold as documentation placeholders until their planned implementations are ready; `horror_slice` is a separately scoped, implemented visual-acceptance example. | Add nonfunctional packages for every planned example immediately. | This preserves the original scaffold decision while recording the later `horror_slice` exception explicitly. |
| 4 | Represent app frame/fixed time with `std::time::Duration`; when the eight-step cap is reached, discard excess whole steps but retain the fractional remainder. | Use floating-point seconds and clear the full accumulator after a capped frame. | Duration avoids avoidable timing drift, and retaining the remainder follows the specified “drop excess” behavior while preserving sub-step progress. |
| 5 | Apply queued OS input before `VirtualInput` events in each `First` stage; a focus-loss event releases all held keys and mouse buttons. | Merge sources nondeterministically or preserve held input after losing window focus. | A fixed source order keeps scripted runs reproducible, and clearing held input matches the existing keyboard-state behavior on focus loss. |
| 6 | Make the new `FramePlan` generic over scene data and keep the old API renderer trait as a compatibility adapter until its legacy scene/material types move in Phase 7. | Add a forbidden dependency from `ribbon_render` to `voxelworks-scene`, or prematurely move scene-rendering types out of their assigned phase. | The dependency table excludes old scene crates from `ribbon_render`; generic frame data preserves the boundary and lets the old renderer keep compiling. |
| 7 | Keep `Scene<'a>` as a type alias for the newly named `RenderScene<'a>` until Phase 9 removes legacy scene imports. | Rename the public type without a compatibility alias. | The old API and GPU renderer still name `Scene`; the alias avoids changing their behavior during the staged migration. |
| 7 | Keep the fixture golden integration test in the legacy CPU crate while the CPU implementation moves. | Add the old testkit crate as a dependency of `ribbon_plugin_rendering` or duplicate its fixture data. | The allowlist excludes testkit from production plugin dependencies, and copying fixture setup would maintain two sources of truth. |
| 10 (pulled forward) | Implement reflection and scene foundations before completing Phase 7's ECS rendering bridge. | Add a second render-only global transform type or defer the render bridge. | The specified bridge consumes `ribbon_scene::GlobalTransform` and `ScenePlugin`; one shared transform source avoids divergent scene state. |
| 11 | Define `VoxelWorldRes` in `ribbon_plugin_voxel` and re-export it from rendering, so both rendering and physics consume one world resource. | Make `ribbon_plugin_physics` depend on `ribbon_plugin_rendering` or duplicate the resource wrapper. | The dependency policy forbids the plugin edge and duplicate wrappers could point at different collision/render worlds. |
| 9 | Rewrite the neutral fixture against the new crates and keep it as `ribbon_plugin_rendering`'s `tests/common` module, with the CPU golden and CPU/GPU parity tests beside it. | Keep a standalone `testkit` crate wired in as a dev-dependency, or leave the tests in the legacy shim crates. | A test-tree module cannot become a production dependency, so the allowlist needs no testkit exception, and the legacy crates lose their last dev-dependencies. The hashes and parity thresholds are unchanged, which keeps the move behavior-neutral. |
| 9 | Replace the STUDS executable's legacy runner with `ribbon_app::App` and ordered platform/scene/rendering/audio/game plugins. The renderer-neutral `WindowFrame` connects the game's selected CPU or offscreen GPU renderer to the winit platform runner without introducing a platform-to-renderer dependency. | Keep `run_with_mode` as an adapter, or make `ribbon_platform` depend on renderer implementations directly. | The new app removes the immediate-mode `App`/`Ctx` trait path; a platform-neutral frame contract keeps dependency direction clean. Legacy shims remain dev-only until the remaining migration and compatibility cleanup are complete. |
| 9 | Delete only the `voxelworks-core` re-exports with no remaining legacy user (`audio`, `physics`) in step 4, and keep `math`, `voxel`, `input` and `time`. | Port `voxelworks-api`, `platform` and `minimal` to the new crates now so all five shims can go. | Those crates are deleted in step 7; porting them would add churn and risk to code that is about to disappear. |

| 9 | Keep `Game` as a compatibility/domain facade, but install its initial values into independent ECS resources and entities for the live runtime. | Rewrite every golden fixture and public helper at the same time as the runtime migration. | The ECS runtime gets separately scheduled player/enemy/pickup systems while existing deterministic fixtures and legacy domain consumers remain compatible. |
| 9 | Expose STUDS renderer choice through `--renderer cpu|gpu|auto` and reuse the existing GPU voxel renderer behind the shared `Renderer<MaterialTable>` and `WindowFrame` contracts. | Keep the game CPU-only or wire a renderer implementation directly into `ribbon_platform`. | The plugin retains backend ownership and platform remains renderer-neutral. STUDS' voxel GPU rendering remains offscreen/readback; the separate `ribbon_plugin_render3d` mesh path presents directly to the native surface until voxel chunks are migrated. |
| Scalability / scheduler | Keep existing `SystemConfig::new` callbacks exclusive and add an opt-in `SystemConfig::parallel` path whose typed access declarations form deterministic conflict batches. Keep a serial fallback and use `SyncResource<T>` for mutable resource data through shared world access. | Execute existing `FnMut(&mut World)` closures in parallel based only on user-authored labels, or migrate all systems to a new parameter-injection API in one step. | Legacy systems may structurally mutate the world and have no inspectable access set. Conservative exclusive barriers preserve compatibility, while typed read/write contracts enable a gradual, auditable migration. The first version uses bounded scoped workers; profile thread startup before investing in a persistent pool. |
| 3D scene | Store `Transform3D` and `GlobalTransform3D` in `ribbon_scene` and reuse `Parent`/`Children`; let `ribbon_plugin_render3d` depend on scene contracts. | Keep a renderer-owned world-space transform and maintain a second, unsynchronized hierarchy. | Parent-child transforms must be shared by mesh rendering, scene serialization and future ray queries. The existing 2D/voxel transform remains separate because its angle and axis convention differs. |

| 3D rendering | Extract camera, built-in mesh, glTF placement and light data into `ExtractedScene3D` in `PostUpdate`, after scene transform propagation. | Query gameplay entities directly inside `FramePass::render`. | A render-facing snapshot separates ECS ownership from GPU command recording and allows future culling, batching and render-graph passes to consume one explicit boundary. |


The horror example uses `ron` and `serde` only to parse its game-owned `room.ron` content schema. `ribbon_plugin_render3d` adds `png` as a test-only dependency to save the optional headless spotlight screenshot under `target/`; none of these dependencies flows into a lower-level engine crate.


| Runtime pacing / measured surface latency | Request Mailbox by default for the primary `ribbon_render::GpuContext` native surface, with FIFO fallback and explicit mode/latency overrides. Keep the desired maximum frame latency at `1`. | Treat Mailbox as universally faster, default to tearing `Immediate`, or optimize shaders from acquisition waits alone. | Three same-workload Windows Release captures per mode resolved to FIFO/1 and Mailbox/1. Median frame-wall P95 was 13.982 ms (FIFO) vs 7.092 ms (Mailbox); acquisition P95 was 13.314 vs 6.885 ms, while mean frame time was slightly higher with Mailbox. This is a reversible, machine-specific pacing choice; per-capture logs now retain the `wgpu` adapter/driver and resolved surface configuration. `tools/run_present_mode_comparison.ps1` provides repeatable remeasurement. |


| Rendering / texture memory audit | Correct generated GLB texture indices and share live GPU textures by decoded pixel content plus dimensions and color-space format; retain only weak cache entries and count shared allocations once. | Upload every material map independently or key sharing only by image index local to one GLB. | Horror Slice's captured 224 MiB material estimate was consistent with repeated 1K mip chains, and the asset generator assigned every map index zero because it measured the not-yet-populated `images` list. Correct references first, then deduplicate identical maps across materials and GLBs without conflating sRGB and linear formats. The estimated post-fix map inventory is ~48.1 MiB, pending target-side capture and visual review. See `docs/TEXTURE_MATERIAL_MEMORY_AUDIT.md`. |


| Asset lifetime / large-scene readiness | Keep the repeated-model grid and lifecycle churn harness opt-in, with strong CPU leases, explicit eviction, generation-aware GPU cache keys, profile counters, and delayed instance-buffer shrink. | Make the default showcase large by default, or infer scale behavior from one small scene. | The harness separates placement/draw count from distinct asset cache entries and exposes residency transitions without changing normal app startup. `tools/run_large_scene_stress.ps1` records reproducible Release captures; passing a small grid is not proof of world-streaming readiness. |
