# STUDS realism upgrade plan

## Audit and baseline (2026-10-16)

The workspace has a dependency-light scene model, CPU and wgpu renderers, and a deterministic golden suite. Legacy Classic and Moody pixels remain protected. Realistic data is carried as plain RGBA mip chains and material texture IDs; asset decode/processing stays outside `voxelworks_scene`. Built-in entities are still boxes (`WARDEN` and `PAGE`).

Baseline on this Windows machine, release build, corridor scene, 320x180, 30 frames/style (`cargo run --release --locked -p voxelworks_render_cpu --example render_bench -- 30`): Classic 0.852 ms/frame; Moody 1.320 ms/frame. This is CPU reference time, not a 1080p GPU measurement.

## Concrete design

1. Keep `voxelworks_core` dependency-free and keep all scene additions as owned/plain data. Put image/glTF decoding, fetching and sprite baking in tooling or `studs`; never add a decoder to `voxelworks_core` or `voxelworks_scene`.
2. Extend `voxelworks_scene` with byte-based RGBA/PBR texture mip levels and explicit stable texture IDs. Add a new Realistic style while leaving Classic and Moody code paths intact. The CPU sampler will use wrapped bilinear/trilinear sampling; the GPU receives the same mip data through a texture array/atlas. Add deterministic tests around sampling and fallback.
3. Add a sprite entity descriptor and renderer-side sprite frame data. A software bake tool will convert a licensed animated GLB into view-angle/frame atlases; CPU and GPU composite sprites after world depth is known, using per-pixel depth and alpha cutout. Keep the box warden as the asset-missing fallback.
4. Extend Realistic-only shading with color lighting, roughness/specular, fog, filmic grade and accessibility-controlled effects. Keep legacy shading branches unchanged. Quality levels gate expensive effects; Low skips shadow rays and costly post effects.
5. Add manifest-driven fetch/processing and generated credits. Keep source downloads outside version control; ship only compact derived assets and verify every manifest hash. Asset loading failures must report a warning and preserve procedural/box fallbacks.
6. Integrate settings and game material assignments after both renderer paths accept the data. Add deterministic tests and document CPU/GPU comparison using `games/studs/examples/ecs_preview.rs` if CI has no headless adapter.

## Work completed and remaining

- Phase 0: repository audit, the original CPU baseline, design, candidate review, and risk notes are recorded here.
- Phase 1: four CC0 Poly Haven PBR sets are downloaded and processed: damaged concrete wall, weathered concrete wall, worn concrete floor, and interior ceiling. The manifest records source, creator, license, usage, local path, and SHA-256. `tools/fetch_assets.py` downloads/caches, converts to 256×256 raw RGBA8 sidecars and ZIPs, generates credits, and validates required metadata, license allowlist, hashes, archive contents, and a 40 MiB shipping cap. Source files are ignored by git. No suitable decal set was selected.
- Phase 2: `voxelworks_scene` has plain RGBA mip chains, stable texture IDs and material PBR sets. CPU and WGSL GPU paths sample albedo, tangent normal, roughness, and AO. The Realistic path is separate; Classic and Moody pixel goldens were not changed. Per-cell PBR UV rotation/flip/tint and deterministic secondary wall-map selection are implemented with a shared cell hash on CPU and GPU; the current seed is stable from voxel coordinates, not level-seeded.
- Phase 3: Realistic has a horror color grade, mapped normals, roughness-driven flashlight response, and AO. Low/Medium presets skip PBR samples; High/Realistic enable them. Existing fog/film effects remain available. One-ray DDA flashlight shadows were added later as Phase B; inverse-square cone penumbra, battery degradation, height dust, bloom, chromatic aberration, and camera breathing remain outstanding.
- Phase 4 (sprite, catch camera, and contact shadow implemented; remaining effects outstanding): OpenGameArt's CC0 source is downloaded to an ignored authoring folder and its provenance is in the manifest and generated credits. `tools/bake_sprites` uses pure Rust `ufbx` to inspect FBX and software-bake a 16-angle × 5-state × 8-frame atlas at 48×96 per cell. The selected Crawlmaster Deluxe has 25 skin clusters with humanoid limb/spine/head names and no animation clips; procedural joint poses supply idle, walk, run/lunge, attack, and frozen variants. CPU and WGSL paths sample sprites, alpha-cut, compare depth against voxel DDA world hits, and apply normal/emissive maps; legacy WARDEN boxes remain the asset-missing fallback. A soft elliptical contact shadow is composited onto visible floor hits on CPU/GPU. The enemy game state selects the sprite state. The baker has procedural pose and synthetic-triangle raster tests; CPU tests cover view/state/frame selection, a wall hit closer than the sprite, and contact-shadow falloff. The Realistic monster golden (`0x88c1a303d3527d1e`) forces a clear corridor view, asserts the atlas is loaded and visible, and pins its output. The Phase 9 migration retires the legacy `gpu_preview -- gpu` runner. `cargo run --locked -p studs --example ecs_preview` exercises the ECS app, while the game binary now selects its CPU or GPU voxel renderer through `--renderer cpu|gpu|auto`. The GPU output is still offscreen/readback; native-surface mesh rendering remains open. Catch now ramps camera pitch upward and narrows FOV over 0.45 seconds; its test checks the attack pose and camera movement. Enemy footstep events now follow walk-animation phase crossings; breathing ambience follows proximity and the first-sight sting already uses the existing enemy event. The footstep crossing curve is tested, though no audio waveform sync measurement has been made.
- Phase 5: visual style and quality choices are exposed and persisted; default settings now select Realistic. PBR maps are loaded once into the material table; missing or invalid assets warn and use the procedural fallback. The legacy `RendererMode::Auto` type is retired. `--renderer auto` now prefers the offscreen GPU voxel renderer when the feature is compiled in and falls back to CPU on GPU initialization failure. Per-cell PBR UV rotation/flip/tint and secondary wall-map use are implemented; decals remain open.
- Phase D (partial): `settings.reduce_flashing` reaches `RenderStyle` in the app scene path. It replaces random flashlight pulses with steady proximity dimming limited to 12%, and disables proximity grain and ray distortion. Tests verify the steady factor is in [0.88, 1.0], with no variation across frame/time for fixed distance. There are no darkness-pulse/chromatic effects to suppress yet, and a time-based luminance slew cap is not implemented; do not count this phase as complete.
- Phase C (partial): Proximity intensity is finite, clamped, and monotonic with distance; looking at the awake monster boosts it by 15%. Both backends use it for vignette/grain and bounded screen-ray distortion (maximum 0.003 UV), while flashlight pulse amplitude grows smoothly with intensity and cannot drop the beam below 45%. Tests cover the curves, limits, NaN handling, and reduce-flashing replacements. Static distortion is a mild ray warp, not a full-screen glitch; darkness pulses, chromatic aberration, and audio-driven intensity remain unimplemented.
- Phase E (partial): automatic CPU quality selection is in place as described above. No CC0 decal set has been selected. Deterministic per-cell material map rotation/flip/tint and secondary wall-map use are implemented. Selection uses stable voxel-coordinate hashing rather than a level-specific seed; decals remain open. The manifest's stale first-line comment is fixed. The asset CI check now rejects any tracked authoring file under `assets/monster/source/` and any tracked file above 40 MiB.
- Phase B (partial): High/Realistic now cast one voxel-DDA visibility ray from each shaded world surface toward the camera flashlight on both CPU and GPU; Low/Medium and legacy visual styles skip it. A CPU fixture proves an intervening voxel blocks the beam, and a falloff test checks finite monotonic light. The GPU shader validated in the local preview after the change. The CPU game-scene fixture measured 8.027 ms/frame at 320×180 (30 frames; three warmups), versus 7.796 ms immediately before adding this shadow ray on the same fixture, an observed +0.231 ms/frame. The Realistic scene golden intentionally advanced to `0x88e9a5e92a1ae692`; Classic and Moody goldens remain unchanged. True inverse-square/cone penumbra, battery degradation, dust haze, bloom, chromatic aberration, and breathing/head bob remain open; this is not full Phase B.
- Phase 6 (partial): deterministic Realistic CPU and monster goldens, monster/PBR manifest validation, atlas size/source checks, and manual GPU preview runs are in place. WGSL compiles and presents on the local adapter. A neutral engine fixture historically had measured CPU/legacy-GPU readback parity (documented in `../history/LEGACY_ARCHITECTURE.md`), but the legacy GPU raycaster and parity test have since been retired. This historical measurement is not parity evidence for the current mesh renderer; parity for the game-specific Realistic scene and GPU frame-time measurements have not been established. CPU benchmark readings on the same Game::new(42), 320×180 fixture: 7.391 ms before monster integration, 7.796 ms after atlas rendering, 8.027 ms after DDA shadows, 8.114 ms after the floor-contact shadow, and 9.163 ms after cell variation. These are CPU timings, not 1080p or GPU results.

## Risks and verification

- Existing CPU/GPU shaders are separate implementations; the legacy golden invariant makes branching essential. New visual tests must use a separate Realistic fixture/style.
- Sprite atlases multiply texture storage by angles and frames. Cap output resolution and retain compact shipping mip levels under the 40 MB budget.
- Network access or upstream URLs may fail on a local machine. The fetch tool is repeatable and hash-checked; it never fabricates images.
- Integrated GPU performance and headless adapter support are environment-dependent. The existing CPU corridor baseline (Classic 0.852 ms, Moody 1.320 ms at 320×180) and the new game-scene benchmark (Realistic 7.391 ms at 320×180) are different fixtures and must not be compared as an apples-to-apples before/after. No 1080p GPU timing has been collected.
- Full visual inspection on a player-sized screenshot remains open. The latest CPU game-scene timing after deterministic material variation is 9.163 ms/frame at 320×180; game-specific CPU/GPU parity and GPU 1080p measurements remain unmeasured. Historical engine-fixture parity results are recorded in `../history/LEGACY_ARCHITECTURE.md`; those results refer to the retired raycaster and do not represent parity with the mesh renderer.
